# ZR 12-10 definitions and street width data

## Question
(1) Verbatim ZR 12-10 definitions of wide/narrow street, street line, corner/interior/through lot, zoning lot, lot coverage, FAR, rear yard, qualifying affordable housing, qualifying senior housing, qualifying residential site, sky exposure plane, base height, street wall. (2) Official NYC dataset giving mapped street width (field, units, version), tested near Convent Ave & W 145 St. (3) Zoning lot vs tax lot.

Source page for section 1 and 3: https://zr.planning.nyc.gov/article-i/chapter-2/12-10 (fetched via curl 2026-10-25). Page header shows "12-10 DEFINITIONS" and section-level "Last Amended 3/26/2026". Each definition carries its own "Last Amended" date, given in the Version column. Definitions in the page are filed alphabetically; "wide street"/"narrow street"/"corner lot" etc. are cross-reference stubs ("see street, wide") that point to the operative entries "street, wide", "lot, corner", etc.

## Not found / open questions
- **"base height"**: NOT FOUND as a defined term in ZR 12-10 (searched the page text for "base height", "maximum base", "height of base"; only "base plane" matched). Base height is likely set in the district bulk sections (e.g. Article II Chapter 3 / Article III), not in 12-10. Not searched in this task.
- **"wide street" / "narrow street" / "corner lot" / "interior lot" / "through lot" / "rear yard"** as literal headwords exist only as "see ..." cross-references; operative text is in "street, wide", "street, narrow", "lot, corner", "lot, interior", "lot, through", "yard, rear".
- **Qualifying residential site**: only the opening captured; full criteria (including non-R1-R5 branches) not transcribed. Re-fetch the page if needed.
- **Units of DCM `Streetwidth`**: NOT FOUND in any text I could read. The PDF's field description was not legible after extraction and the FeatureServer has no field description or domain. Feet is plausible (values 60/75/100, ZR thresholds are in feet) but is UNVERIFIED.
- **Semantics of `>75` and `Unknown`**: NOT FOUND (no documentation seen). Treat as non-numeric/uncertain.
- **Does DCM Streetwidth equal the ZR "width" of a street** (e.g. for the wide-street test, measured between street lines)? UNVERIFIED. DCP describes the layer as "official street names and widths shown on the Official City Map", which is plausibly the legal mapped width; the CSCL width is explicitly paved-area width and should not be used for wide/narrow classification.
- Whether Open Data g6zj-tzgn (updated 2024-05-03 by epoch) lags the DCP-hosted FeatureServer (data edit 2025-12-01): not compared; the Open Data id of the shapefile m2vu-mgzw etc. also exist. A web-search summary said the data.gov listing mentions updates being paused; I did not fetch that page, so UNVERIFIED.
- DCP landing page https://www.nyc.gov/site/planning/data-maps/open-data/dwn-digital-city-map.page returned "Access Denied" to curl; not read.
- Test point coordinates in claim 25 are unsourced; the claim 24 query by name is the reliable test. Matching a lot to its street frontage (which segment adjoins the lot) is not solved by this layer alone.
- ZR text "Last Amended" dates per definition are as shown; the ZR "City of Yes" 12/5/2024 amendments appear in definitions 12, 13, 14, 16. No pre-/post-amendment mixing was attempted.

- None between sources for ZR text. Soft tension: CSCL `streetwidth` (paved width) vs DCM `Streetwidth` (official City Map width) measure different things; do not mix. Also the Open Data copy (updated 2024-05-03) vs live FeatureServer (data edit 2025-12-01) differ in vintage.
